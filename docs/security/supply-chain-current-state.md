# Supply Chain Current State

Date: 2026-07-28

## Scope

This assessment covers the PropertyApi solution projects, package references, Dockerfiles, GitHub Actions workflows, NuGet vulnerability gate, coverage gate, and production-gate container flow.

## Findings Before This Change

| Area | Observed State | Risk |
| --- | --- | --- |
| Test packages | `Microsoft.NET.Test.Sdk` used `17.6.0` and `17.8.0`; xUnit used `2.4.2` and `2.6.6`; runner used `2.4.5` and `2.5.6`. | Test discovery and adapter behavior could differ between projects. |
| Package versions | Versions were embedded in individual `.csproj` files. | Conflicting versions could be introduced silently. |
| Central Package Management | `Directory.Packages.props` was absent. | No repository-level package governance. |
| Lock files | `packages.lock.json` files were absent. | Restore graph could drift without an intentional lock update. |
| NuGet sources | No repository `NuGet.config` was present. | Source policy was implicit and dependency-confusion review was undocumented. |
| GitHub Actions | Workflows used mutable refs such as `@v5`, `@v6`, `@v4`, and `@v2`. | Workflow code could change without a repository diff. |
| Container image | Production gate built images but did not capture an immutable image id. | Scan, SBOM, and promotion could refer to different artifacts. |
| Container scanning | No release-blocking image scan existed in the production gate. | OS and runtime package vulnerabilities could ship. |
| SBOM | No application/container SBOM evidence was generated by the real gate. | Release composition was not auditable. |
| Coverage | Global thresholds were `5%` line and `10%` branch. | Regressions could pass under a very low legacy baseline. |

## Implemented Corrections

| Area | Correction |
| --- | --- |
| Test packages | Unified `Microsoft.NET.Test.Sdk` to `17.8.0`, `xunit` to `2.6.6`, `xunit.runner.visualstudio` to `2.5.6`, and `coverlet.collector` to `6.0.0`. |
| CPM | Added `Directory.Packages.props` and removed project-local package versions. |
| Overrides | Disabled `VersionOverride` with `CentralPackageVersionOverrideEnabled=false`. |
| Reproducibility | Enabled `RestorePackagesWithLockFile` and committed solution project lock files. |
| NuGet source policy | Added repository `NuGet.config` with only `https://api.nuget.org/v3/index.json`. |
| Governance | Added `scripts/validate-package-governance.ps1`. |
| Actions pinning | Pinned all external Actions to 40-character SHAs and added `scripts/validate-github-actions-pinning.py`. |
| Container evidence | Production gate now captures the API image `sha256:` image id after build. |
| Container scanning | Production gate runs Trivy against the captured image id and emits JSON and SARIF. |
| SBOM | Production gate emits application CycloneDX JSON and container SPDX JSON through Trivy. |
| Release manifest | Added `scripts/generate-release-security-manifest.py` for image/SBOM/scan/coverage evidence. |
| Coverage | Added staged threshold policy in `ci/coverage-thresholds.json` and validation script. |
| Dependency automation | Added Dependabot for NuGet, GitHub Actions, and Docker. |

## NuGet Inventory Summary

The direct package set is centrally declared in `Directory.Packages.props`. Security-pinned direct references include `MessagePack 2.5.302`, `Microsoft.Bcl.Memory 9.0.18`, and `System.Security.Cryptography.Xml 8.0.4`.

The current `dotnet list package --vulnerable --include-transitive` result reported no vulnerable packages from the configured sources during local inspection.

## Remaining External Evidence

The repository now contains the controls required to produce release evidence, but a final production PASS still requires a successful GitHub Actions run that builds the container image on the release runner, generates SBOMs, scans the captured image id, and uploads the resulting artifacts.
